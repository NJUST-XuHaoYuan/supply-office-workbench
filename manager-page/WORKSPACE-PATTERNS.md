# 一件工作，一个持续空间

## 统一什么

共性应来自工作的组织方式，而不是某一个业务流程。

| 共性 | 要回答的问题 | 设计约束 |
| --- | --- | --- |
| 目标与来源 | 为什么做，交付什么，依据哪里 | 自主发起、上级下发、规则触发都可成为来源；不强制先有正式工单 |
| 责任与范围 | 谁发起、谁参与、谁处理当前步骤、谁验收 | 发起人不等于执行人；同一时刻可以有多个岗位并行承担责任 |
| 进展与依据 | 已经做了什么，结果可信到什么程度 | 区分 DSH 准备、人员反馈、预测、已验证事实和最终确认 |
| 待处理请求 | 哪一步在等谁，缺什么，需作何判断 | 决策、落实、回复是具体动作；同一工作只出现一行，按当前责任进入待处理或跟进 |
| 成果与记录 | 产生了什么，哪一版，谁确认过 | 可以是报告、表格、现场记录、专业意见、回执；不是所有成果都叫工单 |
| 协同与关系 | 谁向谁下发、补充、询问或汇报，和哪些工作有关 | 沟通有对象与上下文；关联执行不合并原业务的验收责任 |

不将这六项固定成六张卡片。列表只呈现工作名称、当前责任和时限；资料按需展开。没有证据、不需要现场、没有正式回执时，不为了凑布局放空模块。

## 不统一什么

不统一业务步骤、参与角色数量、执行顺序、成果格式或收口条件。核查可以经历分析、现场和验证；文稿可以反复修订；服务事项可以并行补资料和做现场核实；批量计划可以分批推进。不能用同一条四岗位流程图或同一种百分比描述所有工作。

当前呈现层采用通用内容块：指标证据、表格明细、核对清单、文稿及版本。工作数据选择需要的块；同一种块也可以复用到其他业务。例如表格可表达批次、资源清单或会议安排，清单可表达服务缺项、周期作业或会前准备。

初始样例覆盖分析核查、批量计划、客户服务、周期作业和文稿成果。未知工作仍能展示目标、责任、分工、结果和协同，不自动补出线损图表或现场工单。新增业务可提供 `presentation` 元数据组合已有块，页面无需按事项 ID 写分支。

## 保持在哪里

- 顶层只有工作台，主视图为“待我处理 / 我在跟进”。已完成从次级归档入口查看；知道类信息进入简报与动态，必须确认的通知才进入待处理。
- 左侧只选工作，右侧办理当前事情，不再在左侧铺开长详情。正文、输入框为 16px，辅助内容不小于 14px，主要操作目标至少 44px。
- 办理后当前工作暂时保留并注明“已转入跟进”或“已完成”，不中断正在进行的对话；选择其他工作后退出临时保留。
- 用户主动切换分类或搜索时，只展示匹配工作；原选择不匹配则选择第一件匹配工作，两侧同步变化。无匹配时清空选择，不把待处理事项夹进跟进列表。
- 从相关工作或对话引用打开另一件事，只改变当前选择，不重置筛选、搜索或主页面。
- 报告预览与成果目录使用覆盖层。继续修改时，左侧工作与右侧对话一起选择报告所属工作；不允许左边 A、右边 B。
- 页面只维护一个 selectedId，右侧上下文由它派生。两侧使用相同标题，编号留在详情；助手只陈述当前情况和需要本人的意见，不反复堆叠状态。草稿和筛选按岗位保留。
- “发起工作”打开新工作输入并清空左侧选择；创建成功后两侧同时进入新工作。不存在选着旧工作却使用全局助手的状态。窄屏点工作直接进入办理，使用文字按钮“返回工作列表”返回。
- 资料、分工、结果与沟通记录收进“查看详情”，默认关闭。简报、成果目录、归档、演示重置收进右上角“更多”。删除首屏重复说明、小头像、记录版本、日期栏和四个详情页签。

## 责任交接

流程参与人不等于当前责任人。串行步骤完成并确认后才释放下一步；所长决定前，营销员不提前收到线损事项。所长下发后，该事项离开其待处理，保留在跟进，显示营销员当前工作；结果回流需要所长验收时，再回到待处理。

独立分支可以并行，例如客户资料复核和现场核实。两个人看到的是同一事项的不同责任，不是重复处理同一个串行决策。沟通请求要求明确收件人；等待回复归待处理，纯进展通知归动态。

已完成当前动作但仍打开的工作暂时保留，并标记“已转入跟进”或“已完成”。它不计入原待办数量，用户选择其他工作后退出当前上下文，避免办理中突然跳走。

## 成果归属

`context` 记录成果所属的独立报告工作，`matterIds` 记录引用了哪些工作作为依据。两者不能混用：引用线损数据的周报不是线损核查的业务回执。生成报告会创建独立工作，已有报告工作内生成则沿用该工作。审阅报告不会关闭来源任务，旧版本可查看，收口后只读。草稿按所属岗位保管，不因为引用共同事项就广播私人文稿。

## 当前实现边界

本次实现的是通用呈现结构和稳定导航，不是生产级通用流程引擎。既有流转与对话仍采用少量本地演示规则；未配置的请求会说明没有执行。公共协同服务、真实多端一致性、营销 2.0 与真实 DSH 均未接入。

对应实现：`workspace-model.mjs` 提供通用工作视图与类型内容配置；`dialogue.jsx` 负责工作选择、按需详情和对话；`workspace.css` 负责大字号、稳定工作区域与窄屏适配。
